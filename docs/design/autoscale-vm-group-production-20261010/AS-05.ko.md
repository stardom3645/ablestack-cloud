# AS-04: 작업 소유권·중지·재시작 복구 설계

대상: Epic #1346 / 하위 이슈 #1350 / 누적 Draft PR #1356.

## 확인한 결함

- 상태 조회 후 별도 저장으로 동시 확장/축소가 모두 SCALING을 획득할 수 있다. SCALING 자기 전이도 허용된다.
- VM 순번·통계 주기 및 사용자 변경의 전체 VO 저장이 최신 중지 상태를 덮어쓸 수 있다.
- 축소 시 VM 삭제 전에 그룹 매핑을 제거하므로 재시작 후 진행 중 VM을 식별할 수 없다.
- 재시작 시 ENABLED만 모니터링하며 중단된 SCALING을 복구하지 않는다. 같은 LB의 서로 다른 생성 요청도 경쟁한다.

## 상태 및 작업 계약

| 상태/진행 작업 | 활성화 | 중지 | 변경/삭제 | 자동 작업 |
| --- | --- | --- | --- | --- |
| NEW | 생성 구성 완료 후 ENABLED | 불가 | 생성 보상 삭제 | 없음 |
| ENABLED / 작업 없음 | 멱등 | DISABLED | 기존 정책에 따라 변경, 삭제는 기존 cleanup 조건 | 작업 UUID를 원자적으로 획득 |
| SCALING / 진행 작업 | 불가 | DISABLED 의도 즉시 저장 | 진행 작업 완료까지 거절 | 현재 VM 처리만 소유권으로 실행 |
| DISABLED / 진행 작업 | 완료까지 거절 | 멱등 | 완료까지 거절 | 이미 수락한 VM 처리와 복구만 실행 |
| DISABLED / 작업 없음 | ENABLED | 멱등 | 기존 조건에 따라 허용 | 새 확장/축소 없음 |
| REVOKE | 불가 | 불가 | 삭제 진행 | 없음 |

그룹별 MySQL GlobalLock으로 관리 노드 사이에서도 한 작업자만 부수 효과를 수행한다. DB의 작업 UUID·방향·단계·대상 VM·축소 유예 종료 시각은 프로세스 종료 후 보존한다. 시간만으로 살아 있는 작업의 소유권을 빼앗지 않는다. 완료는 같은 UUID일 때만 작업 정보를 지우며, DISABLED를 ENABLED로 덮어쓰지 않는다.

VM 할당·그룹 매핑·대상 기록은 같은 짧은 DB 트랜잭션으로 저장한다. 준비 중 VM도 최대 인원 예약에 포함한다. 축소 대상은 해당 그룹 구성원에서 선택하고 삭제가 확인될 때까지 매핑을 보존한다. 재시작 복구는 해당 VM의 실제 상태와 LB 연결을 확인해 같은 VM을 시작/연결하거나 축소를 마무리한다. 과도 상태에서는 기다리며 새 VM을 만들지 않는다.

활성화/중지/변경/삭제는 별도 그룹 제어 잠금으로 직렬화한다. 중지는 진행 작업 잠금을 기다리지 않으며 새 VM 수락 경계의 행 잠금과 원자적 상태 전이를 사용한다. 같은 LB 생성은 LB 행 잠금 아래 중복 검증 후 저장한다. 모니터 등록/해제는 원자화하며 관리 종료 시 실행기를 종료한다.

## Mold UI

기존 ResourceLayout/DetailsTab·버튼·Alert를 사용한다. 진행 방향/단계와 중지 후 현재 VM을 마무리한다는 설명을 한글/영문으로 표시한다. 진행 중 활성화·수정·삭제와 직접 VM/LB 변경은 비활성화하며 서버도 같은 계약을 검증한다. 기존 라이트/다크 테마 색상을 사용한다.

## 검증

- DAO 원자 비교 갱신, 중복 작업 획득·SCALING 자기 전이·이전 UUID 완료 거절, DISABLED 보존.
- 같은 그룹 확장/축소 경쟁, 중지 후 새 VM 없음, 진행 중 변경/삭제 거절, LB 중복 생성.
- 31 GFS2 Sparse / 32 krbd에서 실제 UI 1→2→3→2→1, 최소/최대 경계, 짧은 왕복 반복, 활성/중지 멱등, 확장/축소 중 중지와 관리 재시작 복구. UI 표시와 VM/ROOT/LB/DB/호스트 증거를 교차 확인한다.
- 한글과 라이트/다크 가독성, 일반 계정/프로젝트 권한 회귀.
- 변경된 Maven 모듈 및 UI 빌드만 수행한다. 장시간 운영 확인은 #1354에서 최종 수행하고, 정책/기간 계산 정확성은 다음 #1349에서 진행한다.

## 프로필·정책·조건 변경과 작업 소유권

중지된 그룹이라도 이미 접수된 VM 처리가 남아 있으면 프로필·정책·조건 변경을 허용하지 않는다. 관련 그룹의 제어/작업 잠금을 그룹 ID 순서로 획득하고 현재 작업을 다시 조회한 뒤 설정을 저장한다. 프로필/정책 탭도 같은 작업 상태로 편집을 제한하며, 비활성화 안내 대신 현재 VM 처리 완료 후 재시도 안내를 표시한다.

# AS-05 VM/LB 수명주기·드레인·삭제 보상 설계 (#1351)

기준: `77715b41b48edd7569591574ebd623911d0dea28`, Epic #1346 / Draft PR #1356. AS-04의 작업 소유권·대상 추적과 AS-03의 정책 평가를 유지한다. 전체 UI 표준 통합(#1355), 예약/프로필 계약(#1352), 운영 조회 확장(#1353), 장시간 확인(#1354)은 이번 범위에 추가하지 않는다.

## 현재 소스에서 확인한 차이

- AS-04는 축소 대상 매핑을 삭제 확인 뒤 제거하지만 UserVmManager.expunge의 조기 콜백이 이 계약을 깨뜨린다.
- cleanup=true 그룹 삭제는 destroy 결과를 무시하고 실패 후에도 그룹 매핑을 제거할 수 있다. LB 설정 false 결과에서 REVOKE가 남을 수 있다.
- LB 신규 등록은 applyLoadBalancerConfig의 false 결과를 무시한다. 기존 DB 매핑을 발견하면 실제 VR 적용을 확인하지 않고 성공으로 간주한다.
- 축소 유예 중 매 주기 LB 제외를 다시 적용한다. 한 번 확인된 제외와 유예 기한을 재사용해야 불필요한 VR 재설정을 줄일 수 있다.
- 축소 인원 판단은 Starting/Stopping을 포함하므로 실제 Running+LB 대상 최소 인원을 별도 확인한다.

## 구현 계약

1. 할당과 멤버/작업 대상은 원자적으로 기록한다. 할당 실패는 오류 이벤트를 남기고 작업을 종료한다. 시작 실패는 해당 VM만 삭제 보상하고, 보상 실패는 DESTROYING_RETRY에 대상/매핑을 보존한다.
2. VM 시작 결과가 없거나 Running이 아니면 LB에 등록하지 않는다. LB 등록/제외 실패는 ASSIGNING_RETRY / EXCLUDING_RETRY에 추적하며 동일 대상만 자동 재시도한다. 내부 예외·인증 정보를 API에 노출하지 않는다.
3. 축소는 Running이며 해당 LB에 포함된 멤버 기준으로 min을 지킨다. 확인된 LB 제외 → 저장된 유예 기한 → destroy/expunge 성공 → 매핑 제거 순서다. 유예 중 같은 LB 명령을 반복하지 않는다. 유예는 최대 대기시간이며 그보다 긴 연결은 종료될 수 있음을 UI에서 설명한다.
4. cleanup=false는 멤버가 있으면 거부하고 VM/LB/그룹을 보존한다. 빈 비활성 그룹은 삭제한다.
5. cleanup=true는 그룹을 비활성화하고 CLEANUP 작업을 먼저 저장한다. 전체 멤버를 LB에서 제외하고 동일 유예를 적용한 뒤 각각 삭제 성공을 확인한다. 일부 삭제가 실패하면 그룹/미삭제 멤버/대상을 보존하며 자동 보상만 계속한다. 자동 보상 완료 후 그룹은 비활성으로 남고 사용자가 삭제를 재시도한다. 프로필·정책·조건·다른 그룹은 제거하지 않는다.
6. 최종 LB 그룹 해제 실패는 비활성 그룹을 보존한다. 관련 DB 정리는 트랜잭션 실패 시 rollback한다. 진행 중 VM 수동 작업 보호는 유지하며 비활성+진행 작업 없음에서만 허용한다.
7. 기존 Mold DetailsTab 상태 안내에 재시도 단계·그룹 정리/삭제 재시도 설명을 추가한다. 삭제 모달과 프로필 유예 설명을 한국어/영어 및 라이트/다크에서 읽을 수 있게 유지한다.

## 검증

- 서버 계약 시험: LB false/예외, 시작 null/비Running/실패, expunge false/예외, 조기 콜백, 유예 중 중복 제외 금지, 최소 서비스 멤버 보호, cleanup 일부 실패/최종 설정 실패/공유 자원 보존.
- 변경 Maven 모듈만 WSL ext4에서 테스트·빌드·RAT, UI 집중 시험·린트·프로덕션 번들. 전체 Cloud/Actions 빌드는 시작하지 않는다.
- 31 GFS2는 Sparse 고정 오퍼링과 실제 QCOW2 파일/할당량을 확인한다. 32는 실제 krbd 경로를 확인한다. 기존 AS01/AS02/AS04 그룹을 유지한다.
- UI에서 정상 인원 범위/반복 왕복/활성 VM 작업 보호, 장애와 대상 추적/자동 복구, 전용 삭제 그룹 cleanup false/true 및 실패 재시도를 확인한다. 영구 삭제 UI 최종 실행은 전용 대상이 준비된 뒤 Computer Use의 실행 시점 확인을 따른다.
- 제한된 HTTP 요청과 장기 연결을 기록하고 실패를 HTTP 상태, 연결 실패, 시간 초과, 연결 종료로 분류한다. LB 변경/기한/VM 삭제/VR 로그와 대조한다. 이전 미분류 HTTP 실패를 서비스 무중단 PASS로 인정하지 않는다.
- 일반 사용자(32)/프로젝트(31), 한국어·라이트/다크 및 VM 메뉴 회귀를 실제 배포 UI에서 확인한다. LIF-01~10 결과는 별도 검증 기록에 실제 증거와 한계를 적는다.
