# SP-10 정책 상세와 운영 정보 조회

정책 목록과 볼륨 탭에서 공통 자원 상세 화면으로 이동한다. VM 메뉴의 ResourceLayout, InfoCard, 작은 메타데이터 목록, 기존 작업 버튼과 업데이트/재시도를 재사용한다. 네 주기와 시간·요일·월간 일자는 한 포매터로 표시하고 등록·변경·중지·재개 완료 알림을 정책 작업으로 표현한다.

`listSnapshotPolicies`는 기존 ACL·정렬·페이지 계약을 유지한다. 모든 권한 있는 독자에게 소유 계정/도메인/프로젝트와 `schedulingenabled`를 제공한다. 관리자의 기존 `fordisplay`는 유지하며, 이는 미래 예약의 중지/재개에 사용되는 플래그다. 이미 실행 중인 작업의 취소나 기존 스냅샷 삭제를 의미하지 않는다.

상세 조회는 `includepolicycontext=true`를 요청한다. 서버는 정책과 현재 원본 볼륨의 ACL 및 소유자 일치를 다시 확인한 뒤 버전 1 운영 정보를 반환한다. 예약 테이블의 미할당 행만 다음 예약으로 표시한다. job이 할당된 행은 수락된 실행이며 다음 예약으로 추정하지 않는다. 관측 시각과 실제 폴링 간격을 제공하며 예약 시각은 실행 보장 시각이 아니다.

최근 실행은 스케줄러가 저장한 CreateSnapshot job의 정확한 policyid/volumeid/소유자/자원 종류로 확인한다. 보존 중인 해당 정책 후보 중 최근 50건만 조사한다. 이력은 만료될 수 있어 영구 감사 기록이 아니며, 검색 결과가 없으면 미확인으로 표시한다. job 인자·결과 원문·경로·자격증명은 반환하지 않는다. 실패는 실제 상태와 코드만 표시한다. 생성 스냅샷은 현재 같은 소유자/볼륨의 삭제되지 않은 자원만 연결한다. 링크는 추가로 UI API 권한과 프로젝트 범위를 따른다.

직접 상세 URL은 UUID·응답 건수·정책/볼륨/프로젝트·운영 정보 버전을 확인한다. 같은 범위의 일시 실패나 불완전 응답은 마지막 성공 데이터를 보존하며 작업을 비활성화하고 재시도를 제공한다. 미존재·권한 상실·사용자/프로젝트/역할/세션 전환에는 이전 데이터를 제거한다. 요청 순서와 범위를 확인해 늦은 응답을 버린다.

검증은 API/서버/UI 집중 검사와 31 GFS2·32 RBD의 실제 API·브라우저·DB·스토리지 증거로 구성한다. 전역 임계값은 0.90을 유지하고 전용 시험 자원만 정리한다. 전체 Cloud 빌드나 기존 FT 작업 변경은 포함하지 않는다.
